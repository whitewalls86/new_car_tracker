# The seam census: every rule, sorted by the seam it holds

Plan 162 working analysis, 2026-09-10. Input to the restructure of
`docs/TESTING.md` and to the question that document cannot currently answer:
which rules are load-bearing partners, which are scaffolding that dies with
its ledger, and which seams have no rules at all.

**Method and confidence.** Every row of the `Asserted by` table (83 rows,
~150 test names) and 12 of the 26 rule modules were read in full during the
Stage AL session that produced this; the remaining modules are classified
from their table rows, and every judgement made on row-text alone is marked
*(row-read)*. Counts come from the table and the ledgers as committed at
`28a277c`, not from memory.

## The frame

Two axes, one cross-cut, one class apart:

- **The seam**: two parties and an owning artifact between them. Closing one
  is always the same move — statements enumerating every direction it can
  drift; one declared owner per truth; everything else derived from the
  owner or compared against it in both directions; unresolvable cases
  ledgered, never skipped; border guards keyed on the shape of deviation;
  shrink-only ledgers; a mutation per guard; a skill per task.
- **The owner's provenance tier** — a property of the artifact, never a
  bucket: **tier 1** generated from our running code (`contracts/*.json`),
  **tier 2** generated by interrogating an installed dependency (Airflow,
  curl_cffi, the S3 API, Postgres itself), **tier 3** recorded empirically
  because nothing publishes anything (cars.com alone). The tier decides the
  instrument and what a diff means — ours says *fix the service*, theirs
  says *they changed, fix our caller* — and nothing else.
- **The mocking cross-cut**: one statement — *a test double derives from the
  owner artifact of the seam it stands on* — instantiated per seam. The
  repository has now written this statement four times
  (`test_no_mock_invents_a_shape.py` says so itself: *"the third time this
  repository has had to state it"*, and the response-object rule made a
  fourth) because the general form had no home.
- **The meta-class**: document ↔ mechanism. The enforcement of the
  enforcement. Deliberately not forced into the seam template.

**The maturity ladder**, which is what "is the rule doing the job" turns out
to mean:

| Grade | State | What the rules look like there |
|---|---|---|
| 0 | unowned | nothing; the seam is a sentence in a table |
| 1 | censused | the drift directions are measured, nothing asserts |
| 2 | compared | readers + both-direction ledgers hold the distance open |
| 3 | standardized | one mechanism; truths derived, not compared; heuristic readers collapse |
| 4 | guarded | only border guards remain, one signature each |

A grade-2 seam's rules are heuristic-heavy **by necessity** — the reader has
to recognise every ad-hoc shape because no single shape exists. The
simplification the restructure should chase is almost never a cleverer
reader; it is moving the seam to grade 3, after which the reader becomes a
lookup and most of its code deletes. The SQL seam is the existence proof.

## The simplification register

Where "change the codebase, not the checker" buys rule deletion. Ordered by
how much reader code dies.

**1. The exit-reader family collapses when handlers derive their
declarations.** `_exit_codes`, `_produced_codes`, `_returns_a_bare_value`,
`route_handlers`'s decorator parsing — hundreds of lines of AST heuristics
(helper recursion, `Response`-suffix conventions, the `Depends`
disqualifier) exist because a handler's exits are freeform. The Stage AL
end state (return the model, raise the envelope member) makes exits
lookups; going one step further — **`responses=` dicts built by a helper
from envelope members** (`responses=refusals(NotFound, DatabaseUnavailable)`)
— makes declaration↔meaning↔code agreement *unconstructable-wrong*, at
which point the meaning rule's raise-site reader (one-helper-level, string
details) deletes and `test_every_route_declares_the_statuses_it_can_return`
becomes a border guard on hand-written dicts. This should be the conversion's
target shape, decided before draining starts, or the drain converts 58
handlers to a halfway convention.

**2. The caller family collapses into the client seam.** Status-read,
outcome-not-discarded, the DAG-status rule, by-hand callers, and unasserted
statement 2 are five rules-or-gaps that one client (routes from a generated
registry, raises on refusal, returns typed outcomes, takes request models)
makes structural. The Airflow copy is the known constraint, with two
established patterns to choose from. This is the single biggest
simplification available and it is already the plan's design — the register
just notes that **five** rules ride on it, not one.

**3. One double-builder collapses the mocking readers.** The four
fabrication readers (bodies, codes, objects, producer shapes at HTTP seams)
each re-derive "which seam is this mock standing on" — and have diverged
once already. A single `service_double(package, verb, path, code,
**overrides)` returning a real `requests.Response` with the contract body
lets all of them shrink toward one border guard with one signature: *no
test configures an HTTP double except through the builder*. The
`.json.return_value` ledger (25) then drains into the same conversion
instead of a parallel one.

**4. Generate the permitted copies.** `container_health/api_envelope.py`
and `api_models.py` are hand-kept copies with (now) an equality rule. A
generation script gated like contracts turns copy-equality rules into
generation gates and removes a hand-sync. Small, cheap, pattern-setting for
the Airflow registry copy the client seam will need.

**5. Generate the external-vocabulary register** (seam 2, tier 2) — same
move as 4, medium value.

**Not worth changing:** the SQL seam (finished), the resolved-compose diff
(already grade 3), the config pairs (volume is intrinsic), the meta-class
(load-bearing as is), the tier-3 corpus rules (a recording is the only
honest instrument; no codebase change makes cars.com interrogable).

## What this means for the restructure

The document's spine should be the seams, each section carrying: parties,
owner artifact + tier, the statements, the rules per statement (name + one
sentence), the ledgers, the maturity grade, and eventually the skill. The
register above says which rules the restructured document should describe
as **scaffolding with a named expiry** versus **permanent border guards** —
a distinction the current flat table cannot express, and the reason
"is this rule redundant" has been unanswerable: within a seam nothing is
redundant, across seams nothing overlaps, and the only rules that ever
become removable are scaffolding whose seam reached grade 3.
